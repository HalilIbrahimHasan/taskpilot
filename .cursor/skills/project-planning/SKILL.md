# Project Planning

1. Start from acceptance criteria and current architecture.
2. Prefer the smallest end-to-end slice that persists real data.
3. List files by database, backend, frontend, tests, and docs.
4. Identify contracts, migration risk, dependencies, and verification commands.
5. Keep deployment and deferred stories outside scope unless approved.

Output ordered implementation steps with a measurable completion condition for each.
